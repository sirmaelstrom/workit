# WP-03: Landing, review lens, gate, merge, release recipes

**Execution:** review-needed · **Review tier:** T2 (adds tests that claim to prove the merge gate; the gate is the run's authority boundary) · **Lane model:** Opus 5.5/high (the managed-repo review branch leaves design room) · **Line budget (E3):** ~550 production lines

**Precondition:** WP-01 merged to `main` (`skills/conduct/scripts/conduct.mjs` with the `land` verb dispatching to `lib/land.mjs` `runLandVerb` with `{ runDir, wpId, flags }`, `lib/state.mjs` with `STEPS`/`STEP_SEAM`, `lib/exec.mjs`, `lib/adapters.mjs` and `lib/recipe.mjs` exist; `state.json` per `_orchestrator.md` § Shared contract). Read `_orchestrator.md` first, then `skills/burn-down/SKILL.md` § Per item step 3 (tiers) and step 4 (Land it: the merge gate), and `skills/slim-review/SKILL.md` § 2 Elicit, § 3 Post, § 4 Adjudicate and § Managed repositories. This WP implements burn-down's gate and drives slim-review's script; it restates and changes neither (MN6, MN9).

**Goal:** pure functions that turn a WP at a PR boundary into the actions that review it at its tier with the lenses that can run (standalone or coordinated), read the lane's adjudication table, record the adjudication, resolve the replied threads, rebase and push it under the merge lock with the review carried across an equivalent rebase (decisions.md D13), check the merge gate at the exact, fresh head, and merge it; one recorder, `recordLandStep`, for every landing action (D19.15); the `land` verb that runs the gate and the post-merge assertion (D15.1); plus the release-recipe functions, the release-eligibility predicate (decisions.md D7, D9, D19.10) and workit's own recipe file.

    0. **fresh base (D19.8):** `git -C <worktree> fetch origin`, then `git -C <worktree> merge-base --is-ancestor origin/<default> HEAD`: exit 0 → fresh; exit 1 → the failure "stale base" and `staleBase: true` (WP-04 re-rebases, never amends). **merge lock (D20):** `state.mergeLock?.wpId === <wpId>` (`'release'` for `--wp release`); a null lock is the failure "merge lock not held", another holder "merge lock held by <wpId>".
    1. **CI** (`gh api repos/<o>/<r>/commits/<head>/check-runs?per_page=100 --paginate`, D18; `gateCheck` unions `check_runs` across every page object `gh` prints, and your premise check quotes the multi-page output shape): every run `completed` with conclusion `success`, `neutral` or `skipped` → pass.     2. **threads**: `pr-review.mjs threads --pr <n> --repo <o/r> --unresolved` exit 0 (exit 8 = unresolved; any other code fails as "threads unreadable").
    3. **review covers head**: the latest reviewed head (a council `reviews[]` entry counts like a posted review, D20), mapped through `wps[].rebases` (a review at `from` covers `to` only when that rebase is `equivalent`), equals `head`; or the tail qualifies. A head mismatch is the failure "head mismatch". `pending` is true only when CI pending is the sole reason `ok` is false; any listed failure makes the result failed.
